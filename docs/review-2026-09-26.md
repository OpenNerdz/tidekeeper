# Repository review — 26 September 2026

The review started from `b41bf72` (2026.9.24.1), after updating the local
checkout from `OpenNerdz/tidekeeper`. It covered production Python modules,
terminal and desktop workflows, authentication, catalog/playback handling,
manifest parsing, transfer/resume/completion state, metadata and media tools,
path/settings persistence, packaging, installers, Docker, and GitHub workflows.
Existing tests were run before changes; the baseline had 422 passing tests.

## Findings addressed

| Area | Problem and resulting behavior |
| --- | --- |
| Account lifecycle | Device login had no cancel action and late replies could affect newer UI state. Cancellation now invalidates the pending challenge, preserves saved login, and ignores old callbacks. Account operations are serialized and block downloads/settings changes. |
| Login feedback | Polling did not honor `slow_down`. Server backoff now updates the desktop timer; deadlines use a monotonic clock. Successful manual sign-in clears both token fields. |
| Shutdown | Background work could outlive the window. Closing cancels cooperative workers and waits for cleanup; an in-progress package update is allowed to finish safely. |
| Terminal behavior | Invalid choices could silently select defaults or partly change settings. Options are validated before saving, failed writes restore in-memory settings, help/version avoid profile initialization, and interruption returns a normal cancellation exit code. |
| Credentials | Manual terminal input was visible and console redaction differed from desktop output. Token input is hidden, shared logging redacts credentials, authenticated calls refuse redirects, and public media requests suppress automatic `.netrc` authentication. |
| Remote input | Video manifest requests did not share the guarded media transport. All HLS requests now use it, resolve relative paths against the final response URL, close responses, and bound streamed reads. Artwork and decoded/expanded manifests have explicit limits. |
| Transfer correctness | Automatic content decoding could invalidate byte-range offsets. Downloads request identity encoding and validate range responses. Connection-slot and destination-lock waits remain cancellable. |
| Concurrent output | Overlapping downloads could write the same media and sidecars concurrently. A shared destination lock covers transfer, processing, and completion recording within the process. |
| Progress | Transfers without preliminary size probes had no useful total. Actual GET responses now supply totals once all constituent sizes are known. |
| Playback completeness | Video selection could exceed the requested resolution despite a lower available variant. Selection now respects the requested ceiling. Preview streams, unfinished HLS, and unsupported multi-period DASH fail clearly instead of reporting partial media as complete. |
| Media verification | Small files bypassed ffprobe checks. They are now verified when ffprobe is available. FFmpeg/ffprobe accept only the needed local-file inputs and media formats. |
| Paths and batches | Root output paths could become relative, disc folders were incompletely sanitized, and nested lists had no aggregate budget. Paths now preserve the selected root and batch expansion has byte/file/item limits. |
| Desktop accessibility | Search, links, results, queue, and token inputs have explicit accessible names; empty-state labels use plain text. Existing workspace/settings/account layouts were visually checked with demo data. |
| Supply chain | Workflow tags were mutable and build permissions broader than necessary. External actions are commit-pinned, permissions narrowed, the crypto dependency minimum updated, and a dependency audit added to CI. |

The changes retain the existing terminal command aliases, settings format,
queue persistence, supported login clients, and clear-stream fallback behavior.
No changes were made to bypass subscription checks, access controls, or DRM.

## Limits of this review

Tests use generated media, demo UI data, and offline API fixtures. No personal
TIDAL credentials or live paid-media downloads were used. Provider availability,
account entitlements, and live sign-in therefore need a normal user acceptance
check. Qt offscreen checks do not replace native screen-reader or interactive
desktop testing on every operating system.

Destination locking is process-local. URL address validation is performed before
requests and is not OS-level network isolation. System FFmpeg/ffprobe and platform
packages need independent updates. A passing dependency audit and test suite do
not establish the absence of every possible defect or vulnerability.
